# 11 — Risiko Desain, Mitigasi & Definition of Done

## Risiko & Mitigasi
| Risiko | Mitigasi |
|---|---|
| Inspection menjadi gimmick | Setiap hotspot penting menghasilkan fakta, tool usage, atau consequence |
| Inventory terbatas → soft-lock | Critical evidence masuk log; objective item punya recovery rule |
| Movement grounded terasa lambat | Respons input tetap cepat; rasa berat dari animasi & audio, bukan input lag |
| Narasi terlalu banyak teks | Prioritaskan clue visual, interaksi, reconstruction |
| Tonal conflict detective vs action horror | Combat jarang; eskalasi bertahap |
| Gore bertabrakan dengan target usia | Target utama 16–18, atau framing implisit untuk versi 13+ |
| Scope terlalu besar untuk tim kecil | Validasi Bab 1 + segmen rumah lewat vertical slice sebelum full production |

## Definition of Done — Core Experience
- [ ] Pemain memahami objective tanpa waypoint berlebihan
- [ ] Pemain menemukan bukti lewat observasi, bukan karena semua objek menyala
- [ ] Inspection menghasilkan informasi yang memengaruhi progres
- [ ] Pemain memahami perbedaan item tangan / kantong / Evidence Log
- [ ] Transisi investigasi → survival terasa sebagai eskalasi, bukan ganti genre mendadak
- [ ] Puzzle bisa diselesaikan dari clue yang tersedia, tanpa tebakan liar
- [ ] Frame rate target tercapai pada vertical slice
- [ ] Ending menyelesaikan kasus tapi tetap meninggalkan konsekuensi emosional (kematian Ray)

## Batasan untuk Agent
- Checklist DoD di atas adalah **gate wajib** sebelum sebuah fitur/level dilaporkan "selesai" — bukan checklist opsional/aspirational.
- Saat mengerjakan task apa pun, cocokkan hasil terhadap tabel risiko: jika solusi yang diusulkan justru memperbesar salah satu risiko di atas, laporkan trade-off itu secara eksplisit, jangan diam-diam diteruskan.
